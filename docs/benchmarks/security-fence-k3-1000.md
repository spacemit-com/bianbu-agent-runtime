# 安全围栏性能基准报告

- 生成时间：2026-10-28 11:03:42 +0800
- 测试主机：bianbu-spacemitk3picoitx / riscv64 / Linux-6.18.3-generic-riscv64-with-glibc2.43
- Python 版本：3.14.4
- 每场景调用次数：1000
- securityd 状态：运行中（bianbu-securityd）
- bwrap 版本：bubblewrap 0.11.1

安全围栏有两类独立开销：每次调用都要执行的进程内判权逻辑，以及调用跨过
 bwrap 边界时的进程/命名空间启动成本。`agent` 模式下每个 Worker 只启动
一次 bwrap；`tool` 模式下每次工具调用都会新建一个 bwrap 进程。

## 测试结果

| 场景 | 总耗时 ms | 平均 ms | 中位数 ms | P95 ms | P99 ms | 错误数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 无围栏裸调用 | 388.704 | 0.389 | 0.344 | 0.773 | 1.02 | 0 |
| 安全中间件：进程内 ALLOW | 396.725 | 0.397 | 0.387 | 0.423 | 0.65 | 0 |
| 安全中间件：securityd 离线回退 | 175919.306 | 175.919 | 171.97 | 199.778 | 214.032 | 0 |
| tool 模式：每次调用启动 bwrap | 46111.555 | 46.112 | 45.027 | 52.117 | 60.077 | 0 |
| tool 模式：bwrap + JSON 工具参数往返 | 69314.132 | 69.314 | 67.261 | 81.284 | 95.45 | 0 |
| agent 模式：bwrap 启动一次，N 次调用在围栏内 | 0.477 | 0.0 | 0.0 | 0.001 | 0.001 | 0 |

agent 模式下，1000 次调用的总墙钟时间为 79.457 ms；bwrap 启动成本摊销到每次调用为 0.0790 ms。

## 开销归因

- 单次进程内判权逻辑（中位数差值）：**0.043 ms**
- 1000 次判权总计（总耗时差值）：**8.021 ms**
- tool 模式单次 bwrap 边界成本（中位数）：**45.027 ms**
- 1000 次 tool 模式围栏总计（总耗时差值）：**45722.9 ms**

## 结论

- 如果围栏随 Worker 启动一次（`agent` 模式），1000 次调用的额外开销约为 **8.0 ms**，单次约 **0.0080 ms**。
- 如果每次工具调用都单独启动围栏（`tool` 模式），1000 次调用的额外开销约为 **45.7 秒**，单次约 **45.0 ms**。
- securityd 在本机运行；本报告仍未包含其 D-Bus 策略判权延迟，
  该边界需要由已注册 Agent 的 Worker 身份调用才能测量。

## 测量限制

- `middleware_failclosed` 包含本机 securityd 桥接回退，这是环境失败路径，
  不是正常的 ALLOW 成本。
- 沙箱场景使用 `/usr/bin/python3` 并显式补充 merged-usr 符号链接，原因是
  本机 bwrap 不接受仓库默认参数；围栏的系统调用与命名空间限制本身未改变。
- securityd 在本机运行，但基准进程不是已注册 Agent 的 Worker，
  因此未包含其 D-Bus 策略判权延迟。
- 本次测试直接调用安全模块与 bwrap，没有启动专家 Agent，也没有调用任何
  LLM；结果反映 Runtime 侧围栏开销，不包含模型推理时间。
